# GitHub 仓库发布与管理规范

在 GitHub 上创建、初始化或正式发布项目仓库时，必须严格遵守以下准则：

1. **必须配置检索标签（Topics / Tags）**：
   - 凡是在 GitHub 上创建或发布新仓库，必须在仓库的「About」区域配置 3~6 个精准、高相关的检索标签（Topics），严禁发布无标签的纯空描述仓库。
   - 标签应涵盖：核心技术栈、项目领域/类型、目标机构/学校/组织（如有）、项目用途等。

2. **标签格式硬性约束**：
   - 严格遵守 GitHub Topic 命名规范：仅支持小写字母、数字和连字符（`-`）。
   - **长度限制**：单个 Topic 长度必须严格控制在 **50 个字符以内**（防止超长导致 GitHub API 或 Web 提交报错）。
   - 若专有名词过长，应使用公认缩写或分词标签替代。

3. **空仓库标签配置时机**：
   - 当初始化空仓库时，若因尚未提交代码而无法在 UI 侧边栏直接配置 Topics，需在完成首个 Commit 推送后立即补充设置，或通过 GitHub API / gh CLI 完成补全。
